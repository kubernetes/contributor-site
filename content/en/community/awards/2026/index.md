#### API Machinery

*Jeffrey Ying, [@jefftree](https://github.com/jefftree)*  
Jeffrey is nominated for his outstanding contributions to core Kubernetes scalability and control plane performance in 2026. His development and landing of EtcdRangeStream represents a major milestone for API Server efficiency, drastically optimizing large range queries, memory footprints, and streaming interactions against etcd. Furthermore, Jeffrey pioneered crucial work introducing controller sharding patterns to scale reconcilers across massive clusters. His deep architectural insight and relentless focus on low-level performance have delivered foundational scalability improvements that benefit cluster operators ecosystem-wide.

*Bryce Palmer, [@everettraven](https://github.com/everettraven)*  
Bryce is recognized for his invaluable contributions to Kubernetes API hygiene, consistency, and static analysis tooling. In 2026, Bryce championed critical enhancements across Kubernetes linters (including kube-api-linter), proactively catching structural and convention discrepancies across API types before they reached production releases. His tooling contributions safeguard API design standards and empower developers across all SIGs to author clean, compliant, and durable APIs.

#### Storage

*Eddie Torres, [@torredil](https://github.com/torredil)*  
Eddie Torres (github: torredil slack: Eddie) led the design and implementation of the Mutable CSINode Allocatable feature, driving it from proposal through GA in Kubernetes v1.36 and enabling accurate, runtime-adjustable volume attachment limits in the scheduler. He also closed a critical data-integrity gap by ensuring volumes are properly unmounted during graceful node shutdown. Across the shared kubernetes-csi sidecars, he has resolved critical bugs including topology cache corruption, concurrent map write races, and VolumeError underreporting. Eddie continues to strengthen the reliability and correctness of Kubernetes storage at multiple layers of the stack.

*Weiwen Hu, [@huww98](https://github.com/huww98)*  
Weiwen Hu (github: huww98, slack: huww98) led the design and implementation of the Mutable PersistentVolume Node Affinity feature, introducing it as an alpha feature in Kubernetes v1.35 to bring flexibility for storage reassignment. He resolved a long-standing Kubelet deadlock by ensuring a single Pod can safely reference the same PVC across multiple internal volumes. In the scheduler, Weiwen introduced passive assume caching to the volume binding framework, eliminating localized scheduling delays caused by cache-ordering races when static PVs are created. He remains highly active in hunting down deeply-rooted storage bugs, diagnosing and resolving test flakes within the integration tests.
